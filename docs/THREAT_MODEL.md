# 威胁模型

## 保护对象

- `auth.json` 中的 OAuth 登录凭据。
- Codex 会话中的提示、源码、终端输出和工具结果。
- 用户项目文件及 Codex 审批、沙箱和 trust 配置。
- Mac/Ubuntu SSH 主机身份与登录边界。

## 信任边界

- `cab` 信任用户安装的官方 `codex` 可执行文件。
- `cab` 信任当前操作系统账号和其私有目录。
- `cab` 不信任项目仓库、符号链接、同机其他用户、第三方 API 地址或自动下载更新。
- 不同 ChatGPT/Codex 账号被视为不同数据边界。

## 防护

- 不读取、解析、打印、复制或写入 `auth.json` 内容。
- 登录检测只调用官方 `codex login status`，因此兼容文件与系统钥匙串缓存，不提取账号身份或令牌。
- 无痕登录通过官方 Codex app-server 的普通 ChatGPT OAuth 接口取得地址，只接受 OpenAI/ChatGPT 官方 HTTPS 域名和 localhost 回调；浏览器以参数数组直接启动，不经过 shell，CAB 不处理 OAuth 令牌。
- SSH 配置导入限制文件数量和大小，忽略通配符 Host，只保存具体别名，不读取 IdentityFile 内容。
- 配置和账号目录拒绝符号链接，分别限制为 `0600` 和 `0700`。
- 配置使用同目录临时文件、`fsync` 和原子 rename。
- 调用 Codex 使用参数数组，不经过 shell。
- 用户配置的新启动轮换默认关闭，只在新的 `cab run` 启动尝试中推进；显式 `--account` 始终优先，额度、认证失败和运行错误不会触发自动重试或即时换号。
- 额度读取只使用官方 app-server 账号接口，并把输出收敛为 CAB 的稳定只读结构；丢弃邮箱和额度重置凭据 ID，不把额度用于自动切号。
- 轮换位置使用拒绝符号链接的 `0600` 文件锁串行更新；账号凭据和会话仍保持独立。
- 过滤继承的 `CODEX_HOME` 与 `CODEX_THREAD_ID`，再设置所选账号目录。
- 桌面账号切换要求用户确认，等待官方桌面进程退出后才以所选 `CODEX_HOME` 重新启动；无法退出时拒绝继续，不静默覆盖正在运行的身份。
- 涉及会话迁移时先按可执行文件路径识别非桌面 Codex 进程；发现 CLI 或编辑器扩展时在关闭桌面端之前中止。关闭后若后续步骤失败，会尝试用原账号目录恢复桌面端。
- 桌面端的会话保留偏好默认关闭，只在用户确认的下一次账号切换中应用；启用后仍保持各账号认证目录独立。
- 不修改 Codex 的审批、沙箱、trust、provider 或模型配置。
- 跨账号共享的任务内容只来自 `sessions/` 和 `archived_sessions/`，必须确认 Codex 已停止并承认上下文披露。本机桌面切换还会从各账号 `.codex-global-state.json` 合并项目目录、顺序、当前项目和会话归属的明确白名单字段；账号身份、插件、提示词和其他全局状态保持隔离。为恢复桌面侧栏可见性，CAB 会备份目标 `state_5.sqlite`，验证完整性后仅删除 `backfill_state` 水位记录，让官方 Codex 自行从共享会话重建该账号的线程目录；不共享 SQLite 文件。
- 会话合并拒绝符号链接、特殊文件和内容冲突，不覆盖已有内容。
- shim 安装替换现有文件前需要 `--force`，并创建可恢复备份；移除时只删除指向当前 `cab` 的 shim。

## 不防护

- 已获得当前 OS 用户权限或 root 权限的攻击者。
- 恶意或被替换的官方 `codex` 二进制。
- OpenAI 服务、ChatGPT 桌面版或 SSH 客户端自身漏洞。
- 用户主动把危险参数传给 `cab run`；参数会原样转发。
- 跨账号恢复会话后产生的服务端数据复制。
- 同一会话被多个进程并发写入造成的逻辑竞争。
- 用户自行配置多个账号、轮换频率或账号资格所涉及的服务条款与组织政策风险。

## 安全使用要求

- 每台机器分别执行官方登录，绝不复制 `auth.json`。
- 使用 SSH 密钥、主机密钥校验和最小权限 Ubuntu 用户。
- 在切换 Remote 账号或迁移会话前结束所有相关 Codex 进程。
- 在切换本机桌面账号前保存并结束正在执行的桌面任务；切换会重启官方客户端。
- 不把账号目录放在云盘、共享盘或 Git 仓库。
- 定期运行 `cab doctor`，并人工检查发布源码及 SHA-256。
